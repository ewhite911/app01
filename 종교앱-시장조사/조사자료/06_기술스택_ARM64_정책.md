## 요약(핵심 결론 10줄)

1. **스택은 React Native + Expo(EAS)** 로 확정 권고. AI 코딩 정확도(TS/React 코퍼스 우위), Mac 없는 iOS 빌드(EAS), 구독(RevenueCat) 모두 가장 매끄럽다.
2. **Windows ARM64에서 Node.js·Expo CLI·JDK·adb·실기기 USB/무선 디버깅은 가능**. 반면 **Android Studio와 Android 에뮬레이터는 Windows ARM64 공식 미지원**(2026-09 기준 변화 없음) → 에뮬레이터 대신 **실기기 + EAS Build**로 간다.
3. Flutter는 Windows ARM64 **stable 채널 미지원**(master만) → 이 환경에서는 비추천.
4. iOS 빌드는 **EAS Build 무료 플랜(월 iOS 15회/Android 15회, 저우선순위)** 으로 시작. 인증서/프로비저닝은 EAS가 Apple 계정 로그인으로 자동 생성·관리. TestFlight까지 Mac 불필요.
5. Google Play 개인 계정(2023-11-13 이후 생성)은 **12명 테스터 × 14일 연속 비공개 테스트** 후 프로덕션 신청 필요(2024-12 20명→12명 완화).
6. RevenueCat은 **월 추적매출 $2,500까지 무료, 초과분 1%**. react-native-iap는 2026-04-26 아카이브됨 → RevenueCat(react-native-purchases) 또는 expo-iap.
7. YouTube 전환은 **https://www.youtube.com/playlist?list=… 표준 링크(Universal Link/App Link)** 만으로 iOS·Android 모두 앱 실행+미설치 시 웹 폴백이 자동. 딥링크 자체는 YouTube API 서비스 사용이 아니어서 API 약관 대상 아님. 다만 "앱이 링크 모음에 불과"하면 Apple 4.2(최소 기능) 리스크 → 루틴·기록·위젯 등 네이티브 가치가 본체여야 함.
8. **iOS SNS 차단**은 Family Controls(Distribution) entitlement가 필수. 개인 개발자도 자기 관리(self-control) 용도로 승인 사례 다수, 심사 기간 4영업일~수 주(2025~2026 지연 사례 다수). **Android**는 AccessibilityService 사용 금지 수준(2026-01-28 강화) → UsageStats + 오버레이 방식만 현실적.
9. 성경: **BSB(2023-04-30 퍼블릭 도메인)·WEB·ASV** 는 무료·무제한, **KJV는 영국 외 PD**, ESV/NIV/NLT/NET은 500절·25% 한도 + 상업용은 별도 허가. 유료 구독 앱은 "상업용"이므로 ESV/NIV/NLT 전체 수록은 라이선스 계약 필요.

# A. 기술 스택

## A-1. React Native/Expo vs Flutter vs 네이티브

**결론**: React Native + Expo(SDK 최신, EAS) 채택. Flutter는 Windows ARM64 stable 미지원과 Dart 코퍼스 열세로 2순위. 네이티브(Swift)는 Mac 없이는 사실상 불가.

| 항목 | RN + Expo | Flutter | 네이티브(Swift/Kotlin) |
|---|---|---|---|
| AI 코딩 에이전트 친화성 | 최상(TS/React 학습량 최대, API 환각 적음) | 중(Dart 코퍼스 상대적 열세) | Kotlin 중, Swift 중(Mac 필수) |
| Windows ARM64 개발 | 가능(Node ARM64 네이티브) | stable 미지원(master만) | Kotlin만 가능, Swift 불가 |
| Mac 없는 iOS 빌드 | EAS Build로 가능 | Codemagic 등 클라우드 Mac 필요 | 불가(Xcode 필수) |
| 구독 결제 라이브러리 | react-native-purchases(RevenueCat), expo-iap | purchases_flutter(RevenueCat) | StoreKit 2 / Play Billing 직접 |
| 커뮤니티 | GitHub 스타 RN 약 126k(2026-07) | 약 178k(2026-07), 아시아·입문자 비중 큼 | 최대 |

**근거**
- 2026 비교 글 다수가 "LLM은 TypeScript/React 학습량이 Dart보다 훨씬 커서 RN 코드가 더 정확·환각 적음"으로 정리. Claude Code 기준 비교 글(note.com)도 RN 우세.
- Expo SDK 57(2026-06-30, RN 0.86) 무중단 릴리스 등 성숙도.
- Flutter Windows ARM64: 아래 A-2 참조.

## A-2. Windows ARM64에서 가능한 작업

**결론**: JS 툴체인(Node/Expo CLI/Metro)·JDK·adb·실기기 디버깅 = 가능. Android Studio IDE·Android 에뮬레이터 = 공식 미지원(x64 에뮬레이션으로 IDE는 기동 가능하나 에뮬레이터는 HAXM/WHPX x64 전용이라 사실상 불가). Flutter = stable 미지원.

| 도구 | 상태(2026-09-17) | 비고 |
|---|---|---|
| Node.js | **ARM64 Windows Tier 2 공식 지원**, MSI 제공(v20/22/24 LTS 모두 `node-vXX-arm64.msi`) | 네이티브 실행 |
| Expo CLI / Metro | Node 위에서 동작 → 가능. ARM64 특화 이슈 보고는 확인 못 함 | Expo는 react-native-windows 미지원(무관) |
| JDK | Microsoft Build of OpenJDK, Azul Zulu가 Windows AArch64 빌드 제공(JEP 388) | Gradle 로컬 빌드는 EAS로 대체 가능 |
| Android SDK cmdline-tools / adb | Java 기반 도구는 동작. adb ARM64 네이티브 여부 **확인 불가**(x64 에뮬레이션으로 동작 보고) | 실기기 연결엔 충분 |
| Android Studio | **Windows on ARM 공식 미지원**(이슈 트래커 2023~, Linaro WOA 프로젝트 "초기 단계") | x64 에뮬레이션으로 IDE 자체는 실행 가능 |
| Android Emulator | **x64 전용, ARM64 PC 미지원**(Microsoft Q&A, Android 문서). WHPX가 x64만 활성 → 커뮤니티 포팅(bjorkepoc)만 존재 | WSA도 2025-03 종료 |
| Flutter | Windows ARM64 빌드는 **master 채널만**, stable 미합류(이슈 #62597/#136417/#179777, 2025-12 문의도 동일 답변) | Dart SDK ARM64는 3.3.0부터 stable |

**근거·이슈 정리**
- 에뮬레이터 불가 → **실기기(Android 폰) + USB/무선 adb + Expo Dev Client**가 표준 워크플로.
- Android Studio를 x64 에뮬레이션으로 띄우면 느리고 에뮬레이터는 여전히 안 됨. Gradle 로컬 빌드 대신 EAS Build 사용 권고.
- Flutter 3.44 stable에서 ARM Windows에서 x64 빌드가 깨진 사례(이슈 #186730) → Flutter 선택 시 ARM64 PC는 추가 리스크.

## A-6. 기기 내부 저장 구조

**결론**
- 기도제목·신앙기록 본문: **expo-sqlite**(구조화, 내보내기 용이). 설정·플래그: **react-native-mmkv** 또는 AsyncStorage. 민감 토큰만 **expo-secure-store**(iOS Keychain / Android Keystore 기반).
- iOS Keychain은 앱 삭제 후 재설치해도 잔존(같은 번들 ID) + 동일 팀 ID 앱 간 공유 가능 → 주의. `WHEN_UNLOCKED_THIS_DEVICE_ONLY` 옵션으로 백업 마이그레이션 제외 가능.
- 파일 데이터 보호: iOS `NSFileProtectionComplete`(Expo 앱은 기본 `NSFileProtectionCompleteUntilFirstUserAuthentication`, 상세 값은 **확인 불가**), Android는 EncryptedSharedPreferences 계열 라이브러리(Jetpack Security는 deprecated 흐름, 대체는 **확인 불가**).
- 백업 제외: iOS는 파일 속성 `isExcludedFromBackup`(expo-file-system 지원 여부 **확인 불가**), Android는 `android:allowBackup` + `dataExtractionRules`로 제외 가능(Expo config plugin 필요).
- 사용자 주도 내보내기: JSON/CSV 파일 생성 후 공유 시트(expo-sharing) — 서버 없는 데이터 이전 수단으로 충분.
- **계정 없는 구독 복원**: RevenueCat 익명 App User ID + `restorePurchases()` → 스토어 영수증 기반으로 복원. 익명↔익명은 alias 병합, 이전 영수증이 식별된 유저 소유면 설정된 "Transfer" 동작에 따라 이전. Apple/Google 모두 "구매 복원" 버튼 제공 의무 있음. 서버 없이 운영 가능.

## A-7. 구독 결제

**결론**: RevenueCat(react-native-purchases) 채택. 요금은 **월 추적매출(MTR) $2,500까지 무료, 초과분의 1%**, 시트/트랜잭션 과금 없음. react-native-iap는 **2026-04-26 아카이브(읽기 전용)** → 대안은 expo-iap(직접 구현) 또는 RevenueCat.

**Apple 3.1.2 준수 체크리스트**(구독 화면 바이너리 내 필수)
- 구독명, 기간, 가격(단위당 가격), 무료체험 기간·종료 후 청구액 명시
- 가격이 레이아웃에서 **가장 눈에 띄는 요소**여야 함(오도 금지)
- 개인정보처리방침·이용약관(EULA) 실동작 링크
- 구매 복원 버튼, 관리/해지 안내(설정 → 구독 링크)

**Google Play 구독**
- 유예기간(grace period): 결제 실패 시 접근 유지 권장, 이후 계정 보류(account hold)에서는 접근 차단 필요.
- **2025-12-01부터 계정 보류 기본값 30일 → "60일 − 유예기간"** 으로 변경(30일 유지하려면 콘솔에서 재설정).
- 취소 흐름에 "일시중지(1주~3개월)" 옵션 제공 가능.

## A-8. YouTube 전환 구조

**결론**: `Linking.openURL("https://www.youtube.com/playlist?list=PLxxxx")` 하나로 충분.
- **iOS**: youtube.com / m.youtube.com / youtu.be 링크는 iOS 9+에서 Universal Link로 YouTube 앱이 자동 실행. 미설치 시 Safari로 자연 폴백. `youtube://` 커스텀 스킴은 Apple 문서에서도 "http 링크 형태"를 안내하며, 커스텀 스킴 사용 시 `LSApplicationQueriesSchemes` 등록 필요 → 표준 https 권장.
- **Android**: https 링크는 YouTube 앱의 App Link로 열림. 강제 앱 실행이 필요하면 `vnd.youtube:PLAYLIST_ID`/`vnd.youtube://playlist?list=…` 또는 `intent://www.youtube.com/playlist?list=…#Intent;package=com.google.android.youtube;scheme=https;end` 사용, `canOpenURL` 실패 시 https로 폴백. Android 11+는 `<queries>`에 패키지 선언 필요.
- **YouTube API 약관**: 앱/웹으로 **딥링크만 하는 것은 YouTube API Services 사용이 아님** → 개발자 정책 적용 대상 아님. 임베드 플레이어를 쓰면 플레이어 변경·오버레이·백그라운드 재생·다운로드·오디오 분리 금지 조항 적용. 본 앱은 앱 내 재생이 없으므로 가장 안전한 구조.
- **스토어 심사(4.2 최소 기능)**: "링크 모음/웹 래퍼"는 거절. 루틴 엔진·로컬 기록·알림·위젯 등 네이티브 기능이 본체이고 YouTube 전환은 마지막 단계라는 점을 심사 노트에 명시하면 문제 없음. 유튜브 영상을 앱의 핵심 콘텐츠처럼 보이게 하지 말 것(브랜딩 가이드).

## B-1. iOS Screen Time API(Family Controls / DeviceActivity / ManagedSettings)

**결론**: 기술적으로 가능하나 **Family Controls (Distribution) entitlement 승인이 관문**. 개인 개발자도 승인되며, "사용자 본인의 앱 사용 제한(self-control)"이 정식 인정 용도. 신청은 번들 ID별 + 각 확장(DeviceActivityMonitor, ShieldConfiguration, ShieldAction)별로 따로. 승인 기간은 4영업일~수 주, 2025-11~2026-05 사이 2~4주 무응답 사례 다수. Expo에서는 Swift 확장 타겟이 필요하므로 **커스텀 Expo Module + config plugin(또는 커뮤니티 `react-native-device-activity`)** 필요 → MVP에서는 제외하고 v1.1 이후로 미루는 게 안전.

**절차**
1. Development entitlement 추가 → 본인 기기에서 즉시 테스트(승인 불필요)
2. Account Holder로 로그인 → https://developer.apple.com/contact/request/family-controls-distribution 에서 번들 ID·용도 설명 제출
3. 확장별 번들 ID 각각 신청
4. 승인 후 Distribution capability 활성화, 재빌드 → TestFlight/App Store

**Apple 심사 관점**: Screen Time 기능이 앱의 중심인가, 부모 통제/가족 안전/개인 디지털 웰빙에 해당하는가, 사용 데이터를 광고·프로파일링에 쓰지 않는가.
**거절 사유**: 모호한 사유서, 부수 기능으로만 사용, 확장 신청 누락.
**사례**: Opal(2022-09 Screen Time API로 성인용 재구축), one sec, ScreenZen(무료), Brick(NFC) 모두 동일 API로 승인·운영 중. 개별 승인 서류는 **확인 불가**(비공개). 개발자 포럼에는 API 버그·제한(앱 선택 토큰 불투명, 50개 제한 등) 불만 다수.

## C-4. AI 종교 콘텐츠·정신건강·연령

**결론**
- Apple/Google에 "AI 종교 상담 앱" 전용 거절 조항은 **확인 불가**. 적용되는 일반 조항: Apple 1.4.1(건강·의료 정보 출처 명시, 검증 불가 시 거절), 4.2(최소 기능 — AI 래퍼 거절 사례 다수), 5.1(개인정보), 2025-11 지침 개정(제3자·AI 서비스에 개인정보 공유 시 명시 고지·동의).
- 미국 주법 동향: NY S 3008(AI 컴패니언은 자살·자해 징후 감지 시 위기 자원 안내 및 AI임을 주기적 고지), Utah HB 452(정신건강 챗봇 고지·광고·데이터 제한). 종교 상담 챗봇을 넣으면 이 범주로 해석될 위험 → **MVP는 AI 대화 기능을 배제**하고, 넣더라도 "정신건강 상담 아님" 고지 + 위기 키워드 시 지역별 핫라인(한국 109, 미국 988) 안내를 기본 탑재.
- 연령 등급: Apple은 2025-07 4+/9+/13+/16+/18+ 체계로 개편, 모든 앱은 2026-01-31까지 갱신 완료 요구. 본 앱(종교 콘텐츠, 외부 링크, 사용자 생성 텍스트 로컬 저장)은 통상 4+ 또는 9+ 가능하나 성인 대상으로 13+ 설정 권고. Google Play는 IARC 설문. 13세 미만 타깃 표시를 하지 않으면 COPPA 직접 적용은 피하나, 2026년 주별 앱스토어 연령 확인법(유타·텍사스 등) 대응이 스토어 차원에서 진행 중.
